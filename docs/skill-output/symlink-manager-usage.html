symlink-manager
사용 결과

설정 파일 하나(ripgreprc)를 dotfiles 로 옮기고 원위치에 심볼릭 링크를 걸기까지, 한 번의 실제 실행을 그대로 기록한 문서입니다.

한 줄 요약

TL;DR

설정 파일 하나를 받아 dotfiles 정본 + 원위치 심볼릭 링크 + 관리 함수 + 커밋을 생성합니다.

설정 파일 ripgreprc
──▶
/devenv:symlink-manager Phase 1 → 5
──▶
✅ 결과물
  • dotfiles 정본
  • 심볼릭 링크
  • 커밋

1. 실행한 명령

/devenv:symlink-manager <file>                        # 범용 형식
/devenv:symlink-manager $SANDBOX/home/.config/ripgrep/ripgreprc   # 이번 실행
SANDBOX

SANDBOX=/tmp/claude-1000/.../scratchpad/symlink-sandbox

이 스킬은 원본을 이동시키고 git commit 까지 하므로, 실제 ~/dotfiles 가 아니라 bash/{claude,app,config,env}/ 로 배치한 샌드박스 dotfiles 레포에서 실행했다.

2. 입력

$SANDBOX/home/.config/ripgrep/ripgreprc 4 lines · ripgrep 설정
  • 1--smart-case
  • 2--hidden
  • 3--glob=!.git/*
  • 4--max-columns=200

분류 판단

Phase 별 결과

  1. PHASE 1 백업 → 이동 → 링크 → 검증

    ripgreprc.backup 생성 후 원본을 bash/config/ripgreprc 로 옮기고 원위치에 심볼릭 링크 생성. 링크를 통해 읽은 내용이 백업과 diff 상 동일함을 확인했다.

  2. PHASE 2/3 관리 함수 + help 추가

    bash/app/ripgrep.bash 에 ripgrep_init, ripgrep_edit_config 를 추가하고 ripgrephelp 에 설명을 넣었다 (bash -n 문법 검사 통과).

  3. PHASE 4 커밋

    커밋 9c12954 feat: manage ripgreprc via dotfiles with symbolic link, 2 files changed / 18 insertions.

  4. PHASE 5 최종 검증

    link / source / backup 존재 확인, 관리 함수 2개 검출.

파일은 어디로 갔나

원위치 · 실제 파일 $SANDBOX/home/.config/ripgrep/ripgreprc regular file

dotfiles 레포에는 아무것도 없고, 설정은 홈 디렉터리에만 존재한다.

원위치 · 심볼릭 링크 $SANDBOX/home/.config/ripgrep/ripgreprc symlink
──▶
dotfiles · 정본 bash/config/ripgreprc source of truth

원위치 경로는 그대로 유지되므로 ripgrep 은 변화를 눈치채지 못한다. 내용은 dotfiles 안의 정본 한 곳에서만 관리되고, 백업 ripgreprc.backup 이 남는다.
