symlink-manager

원래 위치에 있던 설정 파일 하나를 입력받아 dotfiles 레포 안의 정본 + 원위치의 심볼릭 링크 + <app>_init / <app>_edit_* 관리 함수 + 커밋을 산출한다.

OUTPUT 01

dotfiles 정본

파일이 dotfiles 레포 안으로 이동해 버전 관리 대상이 된다.

OUTPUT 02

원위치 심볼릭 링크

원래 경로에서도 그대로 읽히도록 링크가 걸린다.

OUTPUT 03

관리 함수 + help

<app>_init, <app>_edit_<config> 와 <app>help 항목.

OUTPUT 04

커밋

stage 후 git commit 까지 수행한다.

언제 쓰나 / 언제 안 쓰나

쓸 자리와 안 쓸 자리

+

언제 쓰나

  • 설정 파일을 dotfiles 로 버전 관리하면서 원래 경로에서도 그대로 읽히게 할 때.
  • 여러 머신에 같은 설정을 재현 가능하게 깔고 싶을 때.
  • 앱별 관리 함수와 help 항목까지 같이 만들어 두고 싶을 때.
−

언제 안 쓰나

  • Python 프로젝트 툴체인 이전은 mise-migrate, 원격 호스트 SSH 키 위임은 ssh-delegate. 이 스킬은 로컬 설정 파일의 위치와 링크만 다룬다.
  • dotfiles 레포가 bash/{claude,app,config,env}/ 로 배치되어 있지 않으면 전제가 성립하지 않는다.
호출 형식

파일 하나를 넘긴다

/devenv:symlink-manager <file>
/devenv:symlink-manager -h | --help | help

카테고리 — 파일 성격에 따라 결정된다

카테고리용도
bash/claude/Claude Code 관련 설정
bash/app/앱 전용 설정 및 관리 함수
bash/config/일반 설정 파일
bash/env/환경 변수

경로 규약

Source · 정본
~/dotfiles/bash/<category>/<filename>
dotfiles 레포 안에서 실제 내용을 보관한다.
symlink
Target · 원위치
~/<target_dir>/<filename>
앱이 기대하는 원래 경로. 여기에 링크가 놓인다.
동작 단계

Phase 0 → 5

단계를 눌러 상세를 확인한다. 키보드 ← → 로도 이동한다.

PHASE 0

분석

대상 파일 확인, 카테고리 결정, 경로 계획. 변경 전 계획을 announce.
    STOP

    각 Phase 는 첫 실패에서 중단한다.

    ROLLBACK

    Phase 1 의 파일 이동 실패는 .backup 에서 자동 롤백된다. Phase 2 이후의 실패는 자동 롤백되지 않는다 — Phase 1 만 백업 복원 대상이다.

    주의사항 / 제약

    알고 쓰기

    !

    원본을 이동시킨다

    그래서 먼저 .backup 을 만들고 링크를 검증한다. 이미 존재하는 파일을 덮어쓰기 전에는 반드시 확인을 받는다.

    !

    git commit 까지 수행한다

    읽기 전용 감사 스킬이 아니다.

    △

    Phase 2 이후는 자동 롤백 없음

    Phase 1 만 백업 복원 대상이다.

    ✓

    완료 후 직접 검증

    source ~/.bashrc && <app>help 로 새 링크와 함수를 검증한다.
